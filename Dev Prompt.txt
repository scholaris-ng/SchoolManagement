==================================================
4. MULTI-TENANCY
==================================================

This application is SaaS and MUST support multiple schools.

Most business records must belong to:

schoolId

Where branches are supported:

schoolId
branchId

Never trust schoolId supplied by the browser for authorization.

Resolve tenant membership from the authenticated user/session and validate access server-side.

Every tenant-specific query must enforce tenant isolation.

Repository methods should make it difficult to accidentally query records belonging to another school.

Create appropriate compound PostgreSQL indexes such as:

schoolId + admissionNo
schoolId + studentId
schoolId + classId
schoolId + subjectId
schoolId + sessionId
schoolId + date
schoolId + status

Unique constraints that are logically school-specific must normally include schoolId.

Design the data model so that one organization/owner can eventually manage multiple schools or branches.
